# Contributing rules

These rules exist so each member's individual contribution is visible and verifiable at every review.

## Ownership
- Every folder or file has one owner (see README). Only the owner commits to it directly.
- Changes to someone else's file go through a pull request that the owner approves.
- `models/base.py` and `config/` are shared: changes need approval from both other members.

## Commits
- Always commit from **your own GitHub account**, never a shared one.
- Commit small and often, with a clear message: `engine: add filter_step with tensor contraction`.
- Prefix the message with the area: `data:`, `labels:`, `harness:`, `engine:`, `symmetry:`, `neural:`, `docs:`, `tests:`.

## Branches and pull requests
- Work on a branch named `<yourname>/<topic>`, e.g. `sarah/engine-filter`.
- Open a pull request into `main`; one other member reviews it before merging.
- Tests must pass (GitHub Actions runs them automatically) before merging.

## Results
- Never edit files in `results/` by hand. Every table and figure is generated by a script from `results/logs/runs.jsonl`.
- Every experiment calls `log_run(...)` with your name as `author`.

## Weekly log
Add one entry per week to `CONTRIBUTION_LOG.md`: what you did, with links to commits, pull requests and figures.
