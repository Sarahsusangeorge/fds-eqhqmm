# HQMM engine: development notes (owner: Sarah)

What was tried while getting the engine to learn regimes on synthetic data, and
what was found. Useful for paper sections 4.8 (learning) and 8 (limitations).

Synthetic task: 3 assets, K = 3 symbols, two hidden regimes (`synthetic/generate.py`,
seed 0), train days 0–1599, validation 1600–1999, test 2000–2999.
Score quality = AUC of the stress score against the hidden regime on test days.

## Reference numbers (same data)

| --- | --- | --- |
| Uniform guess | −3.296 | — |
| Per-asset frequencies only | ≈ −3.27 | — |
| Joint frequencies, no memory | −3.152 | — |
| Classical exchangeable HMM, 2 states | −3.148 | 0.55 |
| Classical exchangeable HMM, 4 states | −3.102 | 0.87 |
| 10-day average share of extreme moves (no model) | — | 0.84 |

## Findings, in order

1. **The engine maths is correct.** Fast paths match brute-force formulas to ~1e-10;
   autograd gradients match finite differences to ~1e-10 (tests/test_engine.py).
2. **Two regime states are too few.** With the shared daily shock in the data, a 2-state
   model (classical or quantum) spends its states on "up day vs down day" (AUC 0.55).
   4 states (classical) or 2 register qubits (quantum) are needed.
3. **Adam on random windows fails.** It could not even recover data generated by an
   HQMM itself. Full-sequence L-BFGS fits as well as the true model (training loss
   1.727 vs the true model's 1.735), so `train_lbfgs` is now the default.
4. **Reset-mode measurement** (M_k = |0><v_k|) puts all memory in the register and
   reduces filtering to a 2^r x 2^r state: exact (tested against the full engine) and
   far faster; scales to 9 assets.
5. **Stress score**: the predicted share of extreme moves for the next day, Tr(G rho)
   with G = sum_y ext(y) A_y^dag A_y. It does not depend on which register basis the
   model uses for memory (register-state posteriors often did not line up with regimes).
6. **Small initial angles matter.** Large random starts learned only same-day
   co-movement (flat stress score, AUC ~0.5). Initial scale 0.03–0.1:
   - generic circuit, 3 layers, 42 params: AUC 0.78 (one start), 0.58 (another)
   - prototype symmetric circuit, 107 params: AUC 0.72, 0.64, 0.77 across starts
7. **Open problem: run-to-run variance, and likelihood does not identify good runs.**
   Runs with AUC 0.78 and 0.58 had nearly the same validation log-likelihood
   (−3.163 vs −3.157), so "best of several restarts by likelihood" does not reliably
   pick the regime-tracking run.

## Session 2: fixing run-to-run variance

8. **Parallel likelihood.** The whole-sequence likelihood is a product of small
   superoperators S_y = A_y (x) conj(A_y); multiplying them pairwise (tree reduction,
   with rescaling) gives the same number as the day-by-day filter (tested to 1e-8)
   and made training ~3x faster, ~20 s per run (`total_loglik`, `train_lbfgs_fast`).
9. **Choosing restarts by forecast skill, not likelihood.** Over 15 runs (full objective),
   Spearman correlation with test AUC: validation log-likelihood 0.14, validation
   forecast skill (corr of predicted vs next-day actual share of extreme moves) 0.77.
   Best-of-3 expected AUC: 0.61 (by likelihood) vs 0.66 (by skill). Uses no labels.
10. **Training on the big-move pattern only fixes the variance.** The full objective is
    dominated by same-day direction (everyone up / everyone down). Fitting the same
    quantum model to the extreme / not-extreme pattern only (`train_coarse`):

    | Training objective | Test AUC over starts |
    | --- | --- |
    | Full symbols (15 starts) | mean 0.56, range 0.36–0.79 |
    | Big-move pattern only (8 starts) | ≈ 0.77, range 0.74–0.81 |
    | Big-move first, then full fine-tune (6 starts) | mean 0.60, range 0.43–0.76 |

    Fine-tuning on full symbols undoes the gain, so the default is big-move only.
11. **Fair classical comparison on the same big-move data** (exchangeable HMM, 8 starts):
    2 states mean AUC 0.76 (range 0.41–0.87); 4 states 0.72 (0.43–0.87).
    Our generic HQMM: similar average, much smaller spread. Synthetic data and few runs,
    so this is encouraging, not a result.
12. **New defaults** (`HQMMModel`): objective="coarse", selection="skill", 3 restarts.
    `python -m experiments.synthetic_recovery` gives test AUC 0.72 in ~90 s.

**For the team / paper:** the big-move objective is a modelling choice (we detect
volatility regimes, so direction is left out of the training objective). Every classical
and neural baseline must get the same choice for the comparison to be fair; Shriker's
classical HMMs should therefore be fitted to the same extreme / not-extreme counts.

## Session 3: first real-data script (Sa10)

13. **Do not standardise by recent volatility before making symbols.** The plan said to
    divide returns by a trailing 21-day volatility. In a crisis recent volatility rises too,
    so the scaled returns look ordinary and the big-move signal disappears. The script
    divides by each asset's volatility over the training period instead (a fixed number,
    known in advance, so no look-ahead). Tested in `tests/test_first_real.py`.
    **Shriker's S2/S3 and paper §3.1 need the same change.**
14. `experiments/hqmm_first_real.py`: XLF, XLK, XLE; train 1999–2005, validation 2006,
    test 2007–2010; scored against a volatility label (basket 21-day volatility above the
    training 90th percentile). A quick stand-in until the harness exists, not the paper protocol.

## Session 4: integration with the harness, scaling, H1/H2 (details in docs/sarah_findings.md)

15. Reset mode only needs the gate-matrix columns whose asset qubits are |0>. The engine builds just those
    (`build_columns`, `unitary_columns`): 9 assets went from 11 s to 0.23 s per training step, results identical.
    The practical limit is now about 11 assets (memory), not 8.
16. The same categorical HMM goes from AUPRC 0.67 to 0.97 on synthetic data when symbols use
    training-window volatility instead of trailing 21-day volatility (finding 13 confirmed in the harness).
    Still to be checked on real data.
17. With matched symbols the HQMM (0.94) does not beat the classical categorical HMM (0.97) or the spectral
    OOM (0.95): H1 not supported on synthetic data.
18. The equivariant builder is exact (relabelling changes scores by ~1e-15) but dense: 3.8 s per step at
    5 assets, 211 s at 7. H2 above 5 assets needs a faster builder.
